Getting started

Before you begin

  • An existing Sentinel-enabled Log Analytics workspace and the subscription, resource group, name, and region that identify it.
  • Azure DevOps Advanced Security enabled for the relevant repositories and permission to administer project service hooks.
  • .NET 10 SDK, Azure Functions Core Tools v4, Azure CLI, and Azure Developer CLI (azd).
  • Permission to create app resources and role assignments, plus permission to create the table, DCR, workbook, and optional analytics rule in the workspace resource group.
  • An Azure DevOps token with appropriate service-hook and Advanced Security access; keep it out of source control and logs.
Deployment boundary: The commands below create or modify Azure and Azure DevOps resources only when an operator runs them. Confirm your subscription, regions, permissions, and organization policy first.

Provision the integration

Create an azd environment and provide both the application target and the existing workspace coordinates. The DCR is deployed in the workspace region.

azd env new dev
azd env set AZURE_SUBSCRIPTION_ID <application-subscription-id>
azd env set AZURE_LOCATION <application-region>
azd env set SENTINEL_WORKSPACE_SUBSCRIPTION_ID <workspace-subscription-id>
azd env set SENTINEL_WORKSPACE_RESOURCE_GROUP <workspace-resource-group>
azd env set SENTINEL_WORKSPACE_NAME <workspace-name>
azd env set SENTINEL_WORKSPACE_REGION <workspace-region>
azd env set ENABLE_ANALYTICS_RULE true

Set ENABLE_ANALYTICS_RULE explicitly to true or false. After reviewing the target and deployment, an authorized operator can provision the infrastructure and deploy the Function:

azd up

The Bicep entry point orchestrates identity, storage, monitoring, Service Bus, Function, and Key Vault modules. A separate cross-resource-group module configures the existing workspace. The deploying identity needs the necessary access in both subscriptions when they differ.
