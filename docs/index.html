01 / Overview

A shared view of security alerts

This integration forwards events from GitHub Advanced Security for Azure DevOps to Microsoft Sentinel. It does not configure Advanced Security in Azure DevOps or activate a GitHub repository's security features.

01

Stream changes

Created, state-changed, and updated alert events enter a Service Bus queue.

02

Seed active alerts

A separate backfill utility pages through currently active alerts in one Azure DevOps project.

03

Investigate in Sentinel

Use a custom table and workbook, with an optional scheduled rule for active secret alerts.

Delivery is at least once. The Logs Ingestion API does not guarantee exactly-once writes. Deduplicate by EventId when querying.

02 / Architecture

Small components, clear boundaries

A queue separates event delivery from normalization and ingestion. The application resources and existing workspace can be in different resource groups or subscriptions.

  1. PublishAzure DevOps service hooks send alert events to the ghas queue using a queue-scoped Send SAS credential or a service connection.
  2. ProcessA .NET isolated Azure Function reads the queue, normalizes each event, and uses a user-assigned managed identity.
  3. IngestThe Logs Ingestion API sends records through a direct data collection rule (DCR) to GHASAlerts_CL.
  4. InvestigateA Sentinel workbook presents alert triage. An optional hourly rule creates incidents for new or backfilled active secret alerts.

Failed parsing or ingestion causes the Function invocation to fail so Service Bus can retry and eventually dead-letter the message. The workbook's operational panels are opt-in.

03 / Prerequisites

Before you begin

  • An existing Sentinel-enabled Log Analytics workspace and the subscription, resource group, name, and region that identify it.
  • Azure DevOps Advanced Security enabled for the relevant repositories and permission to administer project service hooks.
  • .NET 10 SDK, Azure Functions Core Tools v4, Azure CLI, and Azure Developer CLI (azd).
  • Permission to create app resources and role assignments, plus permission to create the table, DCR, workbook, and optional analytics rule in the workspace resource group.
  • An Azure DevOps token with appropriate service-hook and Advanced Security access; keep it out of source control and logs.
Deployment boundary: The commands below create or modify Azure and Azure DevOps resources only when an operator runs them. Confirm your subscription, regions, permissions, and organization policy first.

04 / Deployment

Provision the integration

Create an azd environment and provide both the application target and the existing workspace coordinates. The DCR is deployed in the workspace region.

azd env new dev
azd env set AZURE_SUBSCRIPTION_ID <application-subscription-id>
azd env set AZURE_LOCATION <application-region>
azd env set SENTINEL_WORKSPACE_SUBSCRIPTION_ID <workspace-subscription-id>
azd env set SENTINEL_WORKSPACE_RESOURCE_GROUP <workspace-resource-group>
azd env set SENTINEL_WORKSPACE_NAME <workspace-name>
azd env set SENTINEL_WORKSPACE_REGION <workspace-region>
azd env set ENABLE_ANALYTICS_RULE true

Set ENABLE_ANALYTICS_RULE explicitly to true or false. After reviewing the target and deployment, an authorized operator can provision the infrastructure and deploy the Function:

azd up

The Bicep entry point orchestrates identity, storage, monitoring, Service Bus, Function, and Key Vault modules. A separate cross-resource-group module configures the existing workspace. The deploying identity needs the necessary access in both subscriptions when they differ.

05 / Connect

Configure Azure DevOps service hooks

The script creates or recognizes project-scoped subscriptions for the three alert events. Existing matching subscriptions are not overwritten; a subscription targeting another queue causes the script to stop.

Option A: queue-scoped Send SAS

Sign in with Azure CLI and set the token in the current PowerShell process. The optional -KeyVaultName stores the queue-scoped credential in Key Vault and requires permission to set secrets.

$env:AZDO_ACCESS_TOKEN = '<pat>'
.\scripts\New-GhasServiceHooks.ps1 `
  -OrganizationUrl 'https://dev.azure.com/<organization>' `
  -ProjectId '<project-id>' `
  -NamespaceName '<service-bus-namespace>' `
  -QueueName 'ghas' `
  -ResourceGroup '<application-resource-group>' `
  -AuthenticationMode Sas
Option B: Azure Resource Manager service connection

Grant the service connection's principal the Azure Service Bus Data Sender role on the namespace or queue. A service connection configured for workload identity federation can be used.

$env:AZDO_ACCESS_TOKEN = '<pat>'
.\scripts\New-GhasServiceHooks.ps1 `
  -OrganizationUrl 'https://dev.azure.com/<organization>' `
  -ProjectId '<project-id>' `
  -NamespaceName '<service-bus-namespace>' `
  -QueueName 'ghas' `
  -AuthenticationMode ServiceConnection `
  -ServiceConnectionId '<service-connection-id>'

06 / Initial load

Backfill active alerts

The backfill utility lists project repositories, follows alert continuation tokens, and enqueues returned alerts whose state is Active. Closed and dismissed alerts are not imported.

$env:AZDO_ORG_URL = 'https://dev.azure.com/<organization>'
$env:AZDO_PROJECT_ID = '<project-id>'
$env:AZDO_ACCESS_TOKEN = '<pat>'
$env:SERVICEBUS_FULLY_QUALIFIED_NAMESPACE = '<namespace>.servicebus.windows.net'
$env:SERVICEBUS_QUEUE_NAME = 'ghas'
dotnet run --project .\src\Ghas.Sentinel.Backfill

The backfill uses DefaultAzureCredential. The selected Azure identity needs Azure Service Bus Data Sender on the queue, and the Azure DevOps token needs access to list repositories and Advanced Security alerts. Initial-load events use deterministic IDs.

07 / Operations

Keep the signal useful

Privacy by default

Raw events and physical and logical locations are excluded by default. Backfill selects an allowlist of top-level alert fields.

Least-privilege paths

The Function uses managed identity for storage, queue receive, and DCR publishing. Sending is separately authorized by SAS or a service connection.

Watch the queue

Inspect dead-letter messages, Service Bus metrics, and Function traces. Enable operational panels in the workbook when needed.

Deduplicate queries

Use EventId to account for retries. The workbook shows the latest event by repository, alert, and branch.

For a simple deduplicated view in Log Analytics:

GHASAlerts_CL
| where TimeGenerated > ago(7d)
| summarize arg_max(TimeGenerated, *) by EventId
| project TimeGenerated, ProjectName, RepositoryName, Severity, State, AlertUrl
| order by TimeGenerated desc
