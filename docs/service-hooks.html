Service hooks

Configure Azure DevOps service hooks

The script creates or recognizes project-scoped subscriptions for the three alert events. Existing matching subscriptions are not overwritten; a subscription targeting another queue causes the script to stop.

Option A: queue-scoped Send SAS

Sign in with Azure CLI and set the token in the current PowerShell process. The optional -KeyVaultName stores the queue-scoped credential in Key Vault and requires permission to set secrets.

$env:AZDO_ACCESS_TOKEN = '<pat>'
.\scripts\New-GhasServiceHooks.ps1 `
  -OrganizationUrl 'https://dev.azure.com/<organization>' `
  -ProjectId '<project-id>' `
  -NamespaceName '<service-bus-namespace>' `
  -QueueName 'ghas' `
  -ResourceGroup '<application-resource-group>' `
  -AuthenticationMode Sas
Option B: Azure Resource Manager service connection

Grant the service connection's principal the Azure Service Bus Data Sender role on the namespace or queue. A service connection configured for workload identity federation can be used.

$env:AZDO_ACCESS_TOKEN = '<pat>'
.\scripts\New-GhasServiceHooks.ps1 `
  -OrganizationUrl 'https://dev.azure.com/<organization>' `
  -ProjectId '<project-id>' `
  -NamespaceName '<service-bus-namespace>' `
  -QueueName 'ghas' `
  -AuthenticationMode ServiceConnection `
  -ServiceConnectionId '<service-connection-id>'
